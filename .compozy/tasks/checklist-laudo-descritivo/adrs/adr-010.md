# ADR-010: Enforce approved-baseline eligibility in every new move-out entry point

## Status

Accepted

## Date

2026-11-03

## Context

The current reference resolver accepts media-only origins, while the user chose an approved inventory baseline as a prerequisite for every new move-out inspection. Manual, scheduled, and project-stage creation converge on the inspection core but can expose different entry points.

## Decision

Validate a same-tenant, same-asset, active or explicitly selected approved inventory version in the common inspection creation path and again when resolving the pinned reference. Reject new move-out work without one using a safe Portuguese error and a route to catalog/approve an origin. Preserve read and rendering behavior for already-created legacy inspections.

## Alternatives Considered

### Alternative 1: UI-only eligibility check

- **Description**: Hide the create button without backend enforcement.
- **Pros**: Small change.
- **Cons**: API and scheduler can still create invalid comparisons.
- **Why rejected**: All creation paths need the same invariant.

### Alternative 2: Migrate all legacy reports first

- **Description**: Convert historical comparisons before enforcing the gate.
- **Pros**: Uniform data model.
- **Cons**: Alters issued history and delays the invariant.
- **Why rejected**: Old reports must remain readable as issued.

## Consequences

### Positive

- New comparisons always identify a reviewed baseline.

### Negative

- Legacy assets need an explicit catalog-and-approve step before new move-out work.

### Risks

- Baseline activation racing with inspection creation could select the wrong version; pin and validate inside one transaction.

## Implementation Notes

"Move-out" means any new inspection created with `FIXED_ORIGIN`. Entry points to guard: `createInspection`, `planInspection` (including project stages), `createSchedule` and its materialization, and onboarding completion; all converge on `inspections/core.Service.Create`. A schedule created before the rollout must fail visibly at materialization, not silently disappear. Version eligibility follows PRD D-5, and video inspections are excluded (PRD D-2). Do not use an editable draft as the reference. Preserve original reference-version IDs in historical snapshots.
