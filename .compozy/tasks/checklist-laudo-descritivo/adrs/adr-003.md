# ADR-003: Use a confirmed template scope for component coverage

## Status

Accepted

## Date

2026-11-03

## Context

Coverage cannot be calculated from items the model happens to detect. The current furnished inventory profile depends on whether voice notes exist, so the same property can be analyzed under different asset policies without an explicit choice.

## Decision

The inspection template supplies the initial expected components, views, and asset profile. An authorized manager may adjust and confirm them before capture. The profile is one of property components, furnished property, or selected items, and is independent of voice usage. The confirmed scope defines the coverage denominator. Clearly visible objects outside it may appear in a separate, informational section without condition or baseline membership.

## Alternatives Considered

### Alternative 1: Infer scope from the image or property record

- **Description**: Let the system decide expected items.
- **Pros**: Less configuration.
- **Cons**: Missing items disappear from the denominator and ownership can be inferred incorrectly.
- **Why rejected**: The user chose an adjustable template scope.

### Alternative 2: Include every visible object

- **Description**: Add all detected objects to the checklist.
- **Pros**: Broad inventory draft.
- **Cons**: Personal objects could become apparent property assets.
- **Why rejected**: The user chose a bounded scope and a separate informational section.

## Consequences

### Positive

- Coverage has a stable denominator and asset treatment is consistent with and without voice.

### Negative

- Managers must confirm scope before capture; templates need maintenance.

### Risks

- A poorly configured template can create misleading completeness; the applied scope and exclusions must be visible.

## Implementation Notes

`Not applicable` requires a reason and leaves the denominator; an uncaptured expected component remains a gap. Voice statements retain their own provenance.
