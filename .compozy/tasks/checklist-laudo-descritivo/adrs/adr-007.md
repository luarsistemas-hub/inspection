# ADR-007: Separate current findings from comparison and version structured schemas

## Status

Accepted

## Date

2026-11-03

## Context

`FINDINGS` currently serves current and comparative modes. Catalog and comparison have separate tasks, but the catalog schema cannot express visual description and assessed scope. The parser validates against the latest fixed task schema, which would break older snapshots after a schema change.

## Decision

Add mode-specific `FINDINGS_CURRENT` and `FINDINGS_COMPARE` task definitions while retaining `FINDINGS` for old snapshots. Add a versioned catalog schema with description, assessed scope, and explicit limitations; keep expected-component coverage computed from the confirmed scope rather than invented items. Resolve parsers by the schema digest/version pinned on each job and preserve older readers. Evaluate a schema-compatible prompt revision before activating the new schema, then promote the chosen version explicitly for future analyses only.

## Alternatives Considered

### Alternative 1: Replace the global `FINDINGS` schema in place

- **Description**: Let the same task name and parser mean the new behavior.
- **Pros**: Smaller task registry.
- **Cons**: Old snapshots become ambiguous and may fail to parse.
- **Why rejected**: Historical read compatibility is required.

### Alternative 2: One combined catalog/findings model call

- **Description**: Merge descriptions and damage findings into one response.
- **Pros**: Potentially fewer calls.
- **Cons**: New coupled failure surface and no proven quality gain.
- **Why rejected**: Existing responsibilities are already separate and the study calls for controlled comparison first.

## Consequences

### Positive

- Clear analysis purpose and reproducible historical data.

### Negative

- Multiple schema readers and prompt definitions remain supported.

### Risks

- A live database prompt may differ from the embedded default; deployment must use explicit version activation, not a blind replace seed.

## Implementation Notes

Pin prompt/model/schema/media-set metadata in analysis generations and report snapshots. Never treat raw voice/transcript text as model instructions.
