# ADR-002: Publish reports automatically with explicit uncertainty

## Status

Accepted

## Date

2026-11-03

## Context

The existing report flow is automatic. The study allows AI observations to appear before human review, while the prototype blocks publication for unreviewed observations and incomplete coverage. The user chose automatic publication even when those limitations exist.

## Decision

Publish a new immutable report version automatically when the available inspection results are ready. Identify unreviewed AI observations, missing component coverage, required key/meter records that are absent, lack of AI consent, and failed analysis in the report. Never turn an empty or failed analysis into a positive condition statement. Human review remains mandatory to activate an inventory as a future comparison baseline.

## Alternatives Considered

### Alternative 1: Require human review for every report

- **Description**: Hold all reports until an operator approves AI observations.
- **Pros**: Strong publication gate.
- **Cons**: Delays delivery and changes the automatic workflow.
- **Why rejected**: The user selected publication with clearly identified review state.

### Alternative 2: Publish only complete reports

- **Description**: Block reports with coverage or required-record gaps.
- **Pros**: Fewer incomplete documents.
- **Cons**: Conceals the actual state of incomplete inspections and prevents delivery.
- **Why rejected**: The user chose to display each gap and pending record.

## Consequences

### Positive

- Recipients can see the available evidence promptly and understand its limits.

### Negative

- Readers must distinguish an unreviewed suggestion from an approved baseline.

### Risks

- A generic “no alerts” label could be misread as complete verification; projections must require evidence and coverage before making that claim.

## Implementation Notes

Publication state and baseline approval are separate lifecycles. Report content is pinned to a version; later corrections produce a new version.
