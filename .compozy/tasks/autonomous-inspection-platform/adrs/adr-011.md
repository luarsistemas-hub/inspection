# ADR-011: Coordinate Slices Through a Typed In-Process Bus

## Status

Accepted

## Date

2026-09-02

## Context

Inspection creation needs immediate answers from assets, templates, participants, and access control, but capability boundaries prohibit direct repository imports and cross-schema queries. HTTP calls inside the monolith add failure modes without isolation value.

## Decision

Provide a typed in-process command/query bus in `internal/platform/mediator`. A slice registers command or query handlers from its single `Setup` entry point. Calling slices define and invoke stable contracts without importing another slice's repository or private implementation.

Each command owns one PostgreSQL transaction and changes only its capability schema. Synchronous queries validate prerequisites before the command transaction. Durable effects in other capabilities use versioned integration events. The system does not share one transaction across handlers and does not introduce distributed sagas for simple synchronous flows.

## Alternatives Considered

### Alternative 1: Direct Service Imports

- **Description**: Export application services from each capability and call them directly.
- **Pros**: Simple call stack.
- **Cons**: Creates compile-time cross-slice coupling and multiple public APIs.
- **Why rejected**: It violates the selected VSA entry-point boundary.

### Alternative 2: Cross-Schema Repository Queries

- **Description**: Let orchestrating slices join tables owned by other capabilities.
- **Pros**: Efficient strongly consistent queries.
- **Cons**: Breaks ownership and makes schema changes ripple across slices.
- **Why rejected**: The product plan explicitly prohibits direct cross-capability table access.

## Consequences

### Positive

- Capability internals remain private.
- Synchronous flows avoid network calls.
- Eventual side effects remain recoverable and idempotent.

### Negative

- The mediator becomes shared infrastructure that requires contract and registration tests.
- Preconditions may change between a query and local command transaction.

### Risks

- Bus contracts could become a hidden global service layer; keep each message use-case-specific and handler-owned.
- Time-of-check/time-of-use races may occur; local constraints and deterministic conflict errors must protect invariants.

## Implementation Notes

The bus propagates `context.Context`, tenant identity, correlation ID, and typed errors. It contains no business rules or automatic transaction management.
