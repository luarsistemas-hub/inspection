# ADR-014: Keep Media Private and Detect Sensitive Content Locally

## Status

Accepted

## Date

2026-09-02

## Context

The current Compose configuration makes the MinIO bucket public, which conflicts with tenant-scoped evidence. Each original can be up to 20 MiB, each inspection or stage can contain up to 200 active photos, and uploads must resume. Faces and documents must be detected before main AI analysis without first exposing potentially prohibited images to an external model.

## Decision

Use private S3-compatible object storage with tenant-prefixed opaque keys. GraphQL creates multipart upload sessions and returns short-lived presigned part operations. Completion verifies object existence, size, actual media type, declared SHA-256, multipart identity, and tenant ownership before marking media uploaded. Originals are immutable; derived display and analysis assets use separate keys.

Accept JPEG, PNG, WebP, and HEIC/HEIF originals up to 20 MiB. Allow at most 200 active photos per inspection or stage, excluding immutable replacement history. A media worker creates normalized derivatives and runs pure-Go local face and document-region detection. It stores no extracted text. Detection must finish before submission; a participant false-positive declaration is recorded and flagged. Only cleared or explicitly overridden derivatives proceed to LiteLLM.

## Alternatives Considered

### Alternative 1: Public Bucket with Unpredictable Keys

- **Description**: Depend on key secrecy for access control.
- **Pros**: Simplifies reads and local development.
- **Cons**: Anyone with a URL can bypass tenant authorization.
- **Why rejected**: It directly violates the PRD.

### Alternative 2: Native ONNX and OCR Runtimes

- **Description**: Package native inference and OCR dependencies in the Go worker.
- **Pros**: Higher initial detection accuracy.
- **Cons**: Adds CGO/native packaging and larger runtime images.
- **Why rejected**: The user selected a pure-Go detector and accepted lower initial accuracy.

## Consequences

### Positive

- Every read and write is explicitly tenant-scoped.
- Interrupted uploads can resume without proxying media through the API.
- Potentially prohibited content is screened locally before external AI analysis.

### Negative

- Pure-Go detection may have lower recall and precision.
- HEIC/HEIF normalization and pure-Go model support require an early compatibility spike.

### Risks

- Incorrect MIME declarations can bypass naive checks; inspect decoded content and reject mismatches.
- Abandoned multipart uploads can consume storage; expire sessions and abort orphaned uploads.
- Detection false negatives remain possible; participant guidance and internal flags are additional controls, not guarantees.

## Implementation Notes

Do not reuse the public `contract` bucket. Pin MinIO and processing dependencies; do not use `latest` images. Object deletion after retention must cover originals, parts, derivatives, reports, and abandoned sessions.
