# ADR-015: Use One Next.js SPA and PWA for Dashboard and Capture

## Status

Accepted

## Date

2026-09-02

## Context

The product needs an internal dashboard and a mobile-first external capture journey. They share GraphQL types, design primitives, localization, and media presentation but use different authentication and authorization models.

## Decision

Create one TypeScript Next.js application with route groups for dashboard and external capture. Generate GraphQL client types from the backend schema. Dashboard routes use OIDC Authorization Code with PKCE and in-memory access tokens. Capture routes use the external HttpOnly session cookie and CSRF token.

Implement installable PWA metadata and a service worker for static application resources. Store pending original blobs, upload IDs, completed part identifiers, metadata drafts, and requirement progress in IndexedDB. Final media verification and submission require connectivity; the product does not claim full offline completion.

## Alternatives Considered

### Alternative 1: Separate Dashboard and Capture Applications

- **Description**: Deploy two independent frontend projects.
- **Pros**: Strong runtime and release isolation.
- **Cons**: Duplicates GraphQL, design, localization, and media code.
- **Why rejected**: The source plan requires shared Next.js dashboard and PWA behavior.

### Alternative 2: Native Mobile Capture Application

- **Description**: Implement iOS and Android capture clients.
- **Pros**: Deeper camera and offline control.
- **Cons**: Outside MVP scope and increases delivery surface.
- **Why rejected**: The PRD explicitly excludes native applications.

## Consequences

### Positive

- Shared contracts and components reduce behavioral drift.
- Capture progress survives refresh and network loss.
- Authentication differences remain isolated by route and client context.

### Negative

- One deployment must maintain strict bundle and route separation.
- Browser media and storage behavior varies across mobile platforms.

### Risks

- Mobile browsers may evict IndexedDB; surface storage state and never claim server completion before verification.
- Service-worker caching may expose stale private data; never cache protected GraphQL responses, media URLs, or report content.

## Implementation Notes

Choose and pin current supported Next.js, TypeScript, GraphQL code-generation, IndexedDB, and PWA dependencies during implementation after compatibility validation.
